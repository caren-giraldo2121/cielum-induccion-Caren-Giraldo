## Autoinvestigación básica

1. ¿Qué es el scope y qué es un closure?
Scope (ámbito) es el contexto donde una variable existe y puede ser utilizada dentro de un programa. Dependiendo de dónde se declare una variable, esta podrá ser accesible o no desde otras partes del código.

Ejemplo: una variable creada dentro de una función solo puede utilizarse dentro de esa función.

Closure (cierre) es una característica de JavaScript que permite que una función recuerde y acceda a las variables de su ámbito externo incluso después de que la función donde fueron creadas haya terminado de ejecutarse. Esto permite conservar datos y utilizarlos posteriormente.

Ejemplo: se crea una función llamada crearContador que contiene una variable llamada contador inicializada en 0. La función devuelve otra función interna que incrementa el valor de contador cada vez que se ejecuta. Aunque la función crearContador ya terminó su ejecución, la función interna sigue teniendo acceso a la variable contador porque mantiene una referencia a su entorno léxico. Esto es lo que se conoce como closure.

2. ¿Cómo funcionan las clases en JavaScript (class, constructor, herencia con extends)?
- Class: Las clases son una plantilla para crear objetos. Encapsulan datos junto con código para trabajar con esos datos.
- Constructor: El método constructor sirve para crear e inicializar un objeto creado con una clase.
- Herencia con extends: permite que una clase herede propiedades y métodos de otra, evitando repetir código.

3. ¿Qué es JSON y cómo se usan JSON.parse y JSON.stringify?

    JSON.stringify() → convierte un objeto de JavaScript a texto JSON.
    JSON.parse() → convierte un texto JSON a un objeto de JavaScript.

4. ¿Qué es el DOM y cómo se seleccionan y modifican elementos?
el DOM es la representación de una página HTML que JavaScript puede manipular. Por medio del DOM podemos buscar elementos, cambiar su contenido, modificar estilos o incluso agregar y eliminar elementos.

¿Cómo se seleccionan los elementos?
Uno de los métodos más utilizados es querySelector(), que permite seleccionar el primer elemento que coincida con un selector CSS. También existe querySelectorAll(), que permite seleccionar todos los elementos que coincidan.
Ejemplo: const mensaje = document.querySelector(".mensaje");

¿Cómo se modifican?
Después de seleccionar un elemento, podemos cambiar su contenido utilizando textContent. Esta propiedad permite obtener o establecer el contenido de texto de un nodo.
Ejemplo: titulo.textContent = "Bienvenidos a mi página";

5. ¿Qué son los módulos ES (import / export)?

los módulos ES permiten separar un programa en diferentes archivos, haciendo que cada archivo tenga una responsabilidad y que podamos compartir solamente las funciones, variables o clases que necesitemos.

export - sirve para sacar o compartir una función, variable o clase de un archivo.

## Autoinvestigación avanzada:

1. ¿Cómo funciona el event loop? Diferencia entre call stack, task queue y microtask queue.

- ¿Cómo funciona el Event Loop?
el funcionamiento de JavaScript en el navegador está basado en un event loop. La idea principal es que existe un ciclo que espera tareas, las ejecuta y después vuelve a esperar nuevas tareas. Cuando una tarea llega mientras JavaScript está ocupado, esta se coloca en una cola para ejecutarse posteriormente.

- Call Stack, Task Queue y Microtask Queue
Call Stack: es donde JavaScript ejecuta el código actual. Las funciones se van colocando en la pila y se ejecutan una después de otra. Cuando una función termina, se retira de la pila y se continúa con la siguiente.

Task Queue: las tareas que deben ejecutarse después se colocan en una cola. El event loop toma una tarea de esta cola cuando el call stack está vacío y la ejecuta. En JavaScript.info estas tareas también se denominan macrotasks.

Microtask Queue: contiene principalmente las tareas relacionadas con las Promises. Cuando termina la tarea actual, el event loop procesa las microtareas pendientes antes de pasar a la siguiente tarea. Esto hace que las microtareas tengan prioridad sobre las macrotareas.

2. Callbacks → Promesas → async/await: ¿qué problema resuelve cada uno?
- Callbacks: resuelven el problema de qué hacer cuando termina una operación asíncrona. Se pasa una función como argumento para que sea ejecutada posteriormente. El problema es que, cuando hay muchas operaciones dependientes, los callbacks pueden quedar anidados y producir un código difícil de leer y mantener.
- Promesas: resuelven principalmente el problema del anidamiento excesivo de callbacks. Permiten encadenar operaciones asíncronas con .then() y manejar los errores de una forma más organizada con .catch().
- async/await: resuelve principalmente el problema de hacer que el código basado en Promesas sea más fácil de escribir y leer. Permite escribir una secuencia de operaciones asíncronas de una forma similar al código síncrono, utilizando await para esperar el resultado de una Promesa.

3. Promise.all, Promise.allSettled, Promise.race: ¿cuándo usar cada uno?
Los tres sirven para trabajar con varias Promesas al mismo tiempo, pero se utilizan en situaciones diferentes.
- Promise.all(): Cuando necesitas que todas las Promesas terminen correctamente para poder continuar. Si una Promesa falla, Promise.all() se rechaza inmediatamente.
- Promise.allSettled(): Cuando quieres esperar a que todas las Promesas terminen, aunque algunas tengan éxito y otras fallen. A diferencia de Promise.all(), no se detiene cuando una Promesa falla; devuelve información sobre el resultado de cada una.
- Promise.race(): Cuando quieres utilizar el resultado de la primera Promesa que termine, ya sea que se cumpla o se rechace.

4. ¿Cómo se manejan errores en código asíncrono?
los errores en operaciones asíncronas se manejan mediante el rechazo de las Promesas. Cuando una Promesa es rechazada, el error puede manejarse con .catch(). Al utilizar async/await, se puede usar try...catch para capturar los errores.

5. ¿Qué es this y cómo cambia en funciones flecha?
this es una palabra clave que se refiere al objeto contexto en el que se está ejecutando el código. Dentro de una función, su valor depende de cómo se invoca la función.
Las funciones flecha no tienen su propio this. En lugar de crear uno nuevo, utilizan el valor de this del contexto léxico que las rodea.
